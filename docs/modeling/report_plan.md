# Report plan

Build the report from the tables and figures generated by `notebooks/nyc_taxi_analysis.ipynb`. No completed report or full-data results are included in this repository. Keep the editable Word document in the team's shared location; the repository holds the reproducible notebook and this plan.

## Suggested structure

1. **Question and data.** Explain completed pickups as the observed outcome, the 2025 taxi and hourly weather sources, and the scope of the top-50-zone forecast versus the all-zone city explanation.
2. **Preparation.** Summarize the actual raw/retained counts from the new cleaning report, exact deduplication, zero-filled hourly grid and DST handling. Refer to [cleaning rules](../corrections.md); do not reuse historical counts.
3. **Exploration.** Choose a small set of hourly/weekly profiles, zone concentration and weather summaries from the notebook. Clearly label the period and units.
4. **Forecast methods.** Describe the calendar ladder, annual harmonics, exposure-adjusted log outcome, training-only smearing, seven-day lag and seasonal-naive baseline. State the chronological January–August / September–October / November–December split and rolling one-hour-ahead evaluation.
5. **Forecast results.** Show validation comparison, identify the selected model, then report its final held-out count-scale errors and baseline skill. Include representative predicted-versus-observed plots. Discuss errors across zones and hours without selecting a model using test results.
6. **Weather analysis.** Explain the train-only city-hour model, clustered inference and HAC sensitivity. Present residual diagnostics, heteroskedasticity evidence, robust block tests, collinearity auxiliary regressions and the joint FWL coefficient check. Report effect intervals with the model and sample.
7. **Limits and implications.** Discuss completed trips versus unmet demand, shared city weather, limited seasonal history, the repeated-hour exposure adjustment and a shared daily curve. Weather associations do not establish causal effects. Forecasting excludes actual future weather.

Appendices can hold the full variable definitions, cleaning report, model tables, diagnostic plots and reproduction details. The body should contain only evidence needed for the conclusions.

## Submission checks

- Run the notebook from a fresh kernel with the actual raw files and review every warning and cleaning count.
- Replace figures and tables using exports from that same run; record dependency versions and configuration.
- Report each result with its model, period, eligible sample and uncertainty method. Avoid uncomputed numbers or claims that a synthetic test is a full-data run.
- State that lag-seven observations are refreshed as time advances. Do not label this evaluation a fixed-origin November–December forecast.
- Explain deliberate changes from the earlier plan: a true chronological holdout, seasonal harmonics instead of unseen month categories, forecast-safe predictors, city-hour weather inference and joint FWL residualization.
- Keep the wording about observed pickups and conditional weather associations consistent throughout.
